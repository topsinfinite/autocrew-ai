## Problem Statement

Autocrew now has paid US customers (sales-won) and more closing soon. There is no post-sale email system. The original impulse was "launch email marketing" (engage subscribers, upsell/cross-sell). After diagnosis, the real job is narrower:

**Sales needs a repeatable way to send a personalized welcome + product-education sequence keyed to the exact package the customer bought** — not newsletter blasts, not immediate upsell.

Today: no logged post-sale friction (curriculum is best-guess). Beehiiv already exists for blog/newsletter capture and must stay separate.

## Demand Evidence

- Paying customers exist (sales-sourced, US). Exact count not provided in-session.
- New customers expected soon → greenfield customer email base.
- Sales team will supply customer details + package/product context per deal.
- **Gap:** post-sale friction is currently **guesswork** (founder selected "we haven't watched or logged post-sale friction yet"). Demand for *email as channel* is inferred from sales ops need; demand for *specific education topics* is unverified.

## Status Quo

- Close happens via sales; no standardized welcome/education cadence.
- Blog newsletter path (Beehiiv + `BlogNewsletter` + `lib/beehiiv.ts`) exists for content subscribers — wrong list and wrong job for customers.
- Blog social kits include Beehiiv email teasers; unchecked "included in newsletter" boxes — content marketing channel, not customer lifecycle.
- Support/product education after close is ad hoc (assumed: Slack/email/calls).

## Target User & Narrowest Wedge

**Operator (primary user of the system):** Autocrew sales / CS admin who just closed a deal.

**End recipient:** The customer's admin / buyer contact who needs to understand what they paid for and how to use product + admin dashboard.

**Narrowest wedge:** Package-keyed welcome + education sequence (Day 0 → ~Day 14), manual send, no upsell in-arc. Personalization tokens only: package/SKU, vertical, admin name, company, go-live date, promised outcome, assigned human contact.

## Constraints

- Premises locked (all agreed): sales-operated playbook posture; Beehiiv out of scope for this sequence; write sequences now from best guesses but end every email with a friction-capture ask; upsell deferred; personalization = structured fields not AI rewrite.
- Chosen architecture: **Welcome Composer page** (Approach B) — render ready-to-copy emails; **manual send** from human inbox.
- Small N customers → no ESP automation required for v1.
- STRATEGY.md still oriented to design partners / multi-location HQ; welcome copy must not assume solo-only persona if package is multi-location.
- Provisional package enum ships with Composer; rename later is allowed.
- **Approved catalog:** all current site sellables (9 packages) — Day 0 for each; steps 1–3 deepen by close volume / friction log.

## Premises

1. v1 is a sales-operated playbook surface, not a marketing automation product. Sales provides context; send is from a human inbox. — **AGREED**
2. Beehiiv is out of scope for this sequence; keep it for Journal/newsletter only. — **AGREED**
3. Full education sequences may be authored now from best guesses; every email ends with a reply/ask that surfaces friction. — **AGREED**
4. Upsell is deferred from the welcome/education arc (optional Day 30+ later). — **AGREED**
5. Personalization = package + vertical + admin name + go-live / success definition — not fancy per-send AI rewriting. — **AGREED**

## Approaches Considered

### Approach A: Playbook page + copy/paste (minimal)
Internal docs/Notion with sequences per package; sales fills tokens manually. Effort S, risk Low. Fastest; no tracking; discipline-dependent.

### Approach B: Internal Welcome Composer page (chosen)
Password-gated page: select package → enter customer fields → renders sequence as ready-to-copy plain-text emails. Manual send. Later: Resend/send API. Effort M, risk Low–Med.

### Approach C: Beehiiv/ESP automation
Per-customer subscriber + package tags + automation. Effort M, risk High for this job (blast feel, list pollution, weak 1:1). Rejected.

## Recommended Approach

**Approach B — Welcome Composer on the marketing site, manual send.**

### Product shape

1. **Intake form (client-only React state — nothing persisted server-side in v1):**
   - Customer admin name, email, company (required)
   - Package / SKU (required — full catalog table above; grouped in UI: Receptionist / Widget / Crews)
   - Vertical: healthcare | legal | restaurant | coaching | home-services | other — required for `ai-receptionist` + crews/widget; **auto-locked** when an industry receptionist slug is selected
   - Locations: `1` | `2-5` | `6+` (required; informs multi-location copy selection when package supports it)
   - Go-live / target date (optional)
   - Promised outcome (required for Day 0 copy — **Copy body disabled** on step 0 if empty)
   - Assigned Autocrew human: name + email (required) = sender
2. **Renderer:** Always show 4 step slots. Each step has `status: "authored" | "stub"`:
   - **authored:** subject + body, copy enabled
   - **stub:** banner "Step not authored — do not schedule"; copy disabled
   - **missing package file:** hard error, no steps
3. **Copy semantics:**
   - **Copy subject** = single plain line, tokens resolved
   - **Copy body** = plain text, markdown stripped to text, friction footer **always appended**, tokens resolved
   - Unknown tokens → red banner + **all copy buttons disabled** for that step
   - Empty optional `{{go_live}}` → substitute `"your target go-live date (TBD)"` (do not fail)
4. **Token set (closed):** `{{admin_name}}`, `{{company}}`, `{{package_name}}`, `{{vertical}}`, `{{locations}}`, `{{go_live}}`, `{{promised_outcome}}`, `{{owner_name}}`, `{{owner_email}}`
5. **Friction footer (non-removable):**  
   `Reply to this email with: (1) where you are in setup, (2) anything confusing. Your Autocrew contact is {{owner_name}} ({{owner_email}}).`
6. **Operator checklist (UI):** before first copy — [ ] Confirm not added to Journal/Beehiiv list
7. **Friction log link** in Composer footer → `docs/post-sale-friction.md` instructions (repo path; open in GitHub or local)
8. **Explicit non-goals for v1:** auto-send, open/click tracking, Beehiiv enrollment, upsell modules, AI personalization, HTML preview, server persistence of PII, customer unsubscribe UI

### Data handling (PII)

- Intake fields live in **browser memory only** for v1. No DB, no localStorage, no URL query params with PII.
- No analytics events that include field values.
- Clear form on navigation away / tab close (default React unmount).
- Do not screenshot or share Composer with filled customer data.
- Usage signal (optional, no PII): client-side checkbox "Day 0 copied (date)" is local-only reminder — not a source of truth. Success criteria still rely on `docs/post-sale-friction.md` entries from humans.

### Cadence (content template)

| Step | Timing | Job | v1 content expectation |
|------|--------|-----|------------------------|
| 0 | Day of close / kickoff | Welcome, what you bought, who to reply to, 7-day success definition | **Authored for all 9 packages** |
| 1 | Day 2–3 | Setup / first value path | Authored for packages with live closes; else `stub` |
| 2 | Day 5–7 | Admin dashboard / product surface tour | Same as step 1 |
| 3 | Day 10–14 | "Are you live?" + collect stuck points | Same as step 1 |

Upsell / cross-sell: **out of sequence**. Park as future Day 30+ doc, not Composer v1.

**Content strategy (aligned with approval):** Ship Day 0 across the full site catalog so sales can pick any offering. Deepen steps 1–3 per package only after friction log entries for that slug (or after sales flags which SKUs close most).

### Friction log schema

Path: `docs/post-sale-friction.md`

Per entry:

```
### YYYY-MM-DD — {customer_pseudonym} — {package_slug}
- Step: 0|1|2|3
- Stuck point: …
- Resolution (if any): …
```

Success criterion: ≥3 stuck-point entries within first 3 Composer-assisted closes.

### Relationship to Beehiiv

- `lib/beehiiv.ts` + blog newsletter: **prospect/content list only**.
- Customer welcome: Composer → human Gmail/Outlook send from assigned owner.
- Never add paying customers to the Beehiiv publication as a side effect of onboarding.
- Operator checklist is the v1 control; technical cross-check deferred.

## Success Criteria

- Sales can produce a complete Day-0 email for a closed deal in **&lt; 5 minutes** without inventing copy.
- 100% of Composer copy-body output includes friction-capture footer.
- Zero customer emails enrolled into Beehiiv via this flow (checklist + sales discipline).
- Within **3 closes** using the Composer: `docs/post-sale-friction.md` has ≥3 concrete stuck points.
- No upsell CTAs in steps 0–3.
- No server-side persistence of customer PII in v1.
